CRAWLSTUDIO / TEAM GUIDE

Your first website audit.

CrawlStudio runs its crawl engine on a server. Your team controls it from Chrome, Edge, Firefox, or Safari—no installation on each teammate’s computer.

← Open the crawler

1. Open your team’s URL

Use the HTTPS address your administrator shares, such as https://crawl.yourdomain.com. Enter the team username and password when the browser asks. Everyone on this workspace can see the saved crawls.

For local use on the computer running the app, http://localhost:4310 works in a regular browser too. A localhost address does not point to that computer when opened by a teammate.

2. Run a small crawl first

  1. Enter the site’s full canonical URL, including https://.
  2. Set a page limit of 50–100 for the first audit.
  3. Open Crawl configuration. Keep robots.txt enforcement on. Enable rendering only when the site needs JavaScript and the administrator has installed Chromium.
  4. Select Start crawl. The dashboard updates as pages are processed.

Only one crawl runs at a time in this shared workspace. Coordinate with your team before stopping a crawl.

3. Read the results

  • Crawl overview: response codes, URL list, and filters. Click a page for its record.
  • Issues & opportunities: findings grouped by audit type.
  • Evidence audit: prioritized findings with evidence, confidence, impact, and a fix. Confirmed means an observation; it does not guarantee a ranking effect.
  • Site visualisation: links and directory groups within the crawl.
  • Crawl comparison: compare two saved snapshots after changes.

4. Download and share

Use Download PDF, Full report, Action plan, and HTML report in Evidence audit. Overview also exports JSON, CSV, and XML sitemaps. Teammates can open the same crawl under Saved crawls.

Reports can include crawled page content. Share them with the intended recipients.

5. Integrations and schedules

Your administrator configures API credentials on the server. Select a service in Integrations & AI and run it explicitly. Some provider calls have charges.

Schedules run while the server is online. On managed hosting, deployments or restarts can interrupt active crawls. A persistent server and data volume are recommended for reliable team use.

What this team edition includes

One shared workspace, one active crawl, and a shared browser sign-in. It does not provide individual accounts, permissions, billing, or isolated client workspaces. Use an HTTPS address and share the password only with your team.

Hosted mode blocks crawling private and local network destinations. For intentionally auditing internal sites, ask the administrator to use a separate trusted local installation.
